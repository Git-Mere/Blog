- Inode: 리눅스 시스템에서 파일이 저장되는 형태? 같은 거
파일이 저장될 떄는 데이터 블록 형태로 저장이 되는데, Inode가 어떤 데이터 블록에 이런 데이터가 있는지 알고 있음. 또한 permission, access time 등 여러 정보들도 포함. 하지만 우리가 inode를 기억하고 파일에 접근하는 것은 어렵기 떄문에 우리는 파일 이름을 사용 예)hi.txt 이것이 그 파일의 inode를 포인팅함.

- 하드 링크 : 파일에는 링크가 존재하는데, 이 링크는 쉽게 보면, 그 디렉토리에서 보이는 거임. 즉 a라는 유저가 hi.txt를 가지고 있고 그게 디렉토리에서 보이면 a는 그 파일에 대한 링크를 가진거임. 이렇게 직접적으로 hi.txt가 그 파일에 대한 inode를 가리키는 것이 보이면 hard link임. 파일의 링크가 0이 되면 디스크에서 삭제됨. 오직 파일만 가능함. 폴더는 불가 그리고 같은 파일시스템에서만 작동함.(c 드라이브에서 d드라이브에 링크 생성 불가)

- 소프트 링크 : 하드링크를 가진 파일, 폴더를 가리키는 것. (바로가기) 소프트링크는 다른 파일시스템에서도 작동함.(c드라이브에서 d드라이브로 링크 생성 가능)


- 명령어 ln : 이 명령어는 그 파일에 대한 하드링크를 만들어준다. 하드링크를 만들면 선택한 파일이 원하는 디렉토리에 생성된것처럼 보임. 하지만 디스크에서 그 파일이 차지하는 크기는 같고, 그저 그 inode를 가리키는 링크가 하나 더 생긴것이다.
권한도 그대로 복사됨. 그래서 만약 그 파일에 권한 없으면 링크를 만들어도 접근 불가.
  - 옵션
  - -s (타겟) (생성할 바로가기 파일이름): 소프트 링크 만들기 

- 명령어 usermod -a -G family Amy
  - 옵션
  - -a : append(기존 그룹 유지)
  - -G (그룹 이름) : 그룹 추가

- 명령어 useradd -G family Amy
  - 사용자 처음 생성할 때만 사용
  - 옵션
  - -G (그룹 이름) : 그룹 추가

- 명령어 chmod (숫자 or 문자) (파일이름)
  - 파일의 권한을 바꾸는 명령
  - 여기서 그룹은 그 파일을 만든 사용자의 기본 그룹을 따른다.
  - 숫자로 할 시에는
    r - 4, w - 2, x - 1
    ex) chmod 660 (파일이름) - 소유자 + 그룹 공유
    ex) chmod 777 (파일이름) - 모두 읽기/쓰기/실행
    ex) chmod 700 (파일이름) - 소유자만 접근 가능

  - 문자로 할 시에는
    chmod 대상자 연산자 권한 파일
    대상자
    u : user
    g : group
    o : other
    a : all

  - 연산자
  - + : 추가
  - \- : 제거
  - = : 정확히 설정

  - 권한 문자
  - r : 읽기
  - w: 쓰기
  - x : 실행

  - ex) chmod u=rw,g=rw,o= (파일이름) == chmod 660 파일

보통 권한 조금씩 수정할 떄 사용
chmod g+w 파일

1. 본인이 그 파일의 소유자
2. 바꾸려는 그룹이 본인이 속한 그룹

- 3) 명령어 chgrp (그룹) (파일)

- 1) chown (사용자:그룹) (파일)

- 명령어 echo
  - 가장 기본적인 출력 함수
  - 여기에 >, >>을 섞어쓰면 파일에 작성 가능
  - ex) hi > list.txt 하면 list.txt가 없으면 생성, 있으면 내용 완전 덮어씀.
  - ex) hi >> list.txt 하면 list.txt가 없으면 생성, 있으면 파일 내용 뒤에 인풋을 추가함.
